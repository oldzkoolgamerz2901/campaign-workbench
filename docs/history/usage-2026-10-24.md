# Earlier detailed usage instructions

Historical instructions, retained without dropping details. Current behavior is in the [user guide](../user-guide.md); archive formats and UI descriptions below apply at the time originally written.

## Campaign source library

Use **Manage campaign** to register a campaign using a display name and an available folder path, refresh its library, or edit source rules. The shared header switches campaigns in preparation and reading. Registrations, source rules, and the last selected campaign persist in PostgreSQL. Opening a campaign scans its Markdown; **Refresh library** explicitly captures later edits. Reading and search use the same captured text until refresh succeeds. If scanning fails, the previous capture remains readable and the error identifies the affected read. Before a first successful capture, the library remains empty.

**Source rules** shows editable include/exclude patterns, one per line. Paths are relative to the registered folder, with `/` separators. `*` and `?` match within a segment; `**` spans directories. `**/*.md` includes root and nested Markdown, case-insensitively. Exclusions win. Defaults exclude hidden files/directories, `node_modules`, `build`, `dist`, `target`, `coverage`, and `AGENTS.md`/`CLAUDE.md`. Symlinks are not followed. Changing rules marks the current capture as needing refresh; it stays readable until successful refresh. Duplicate resolved directories are rejected.

Search matches the trimmed query literally and case-insensitively against document paths, headings, and section text. Results open their matching block, including under repeated headings. Markdown supports headings, lists, tables, and code; raw HTML is escaped and images are omitted. Relative Markdown links (including encoded spaces) and heading anchors resolve within the capture. Heading anchors use lowercase heading text, remove punctuation except `_`/`-`, replace spaces with `-`, and add numeric suffixes for collisions. Missing, excluded, or unsupported targets are identified. External HTTP(S) links open only after a click.

A refresh replaces the current capture rather than retaining history. Old references prompt a library reload. There is one refresh at a time per campaign; scans are outside database transactions and publication is atomic. Concurrent filesystem edits cannot be guaranteed to represent one instant; detected unreliable reads fail the scan. No background watching, source authority classification, assets, campaign-file editing, backup/restore, or live-session functionality is included. Chromium is the current developer acceptance browser; Safari/WebKit support is deferred. The development startup above remains required.

## Manual writing and card previews

Choose **Write** in the shared campaign header. **Write**, **Prepare**, and **Play** keep the same navigation and save-status positions. Menus use the dark workspace theme. Backend availability is checked automatically on startup and return to the window; only a failed check shows a connection notice and retry. The writing desk uses the selected campaign and keeps its drafts in PostgreSQL, separate from campaign files and prepared sessions. Expand **New draft** to choose a type and optionally start with suggested headings. The title and Markdown body are visible immediately; expand **Card details** to edit the type, metadata status, optional tags/summary, and suggested export path. **All** and the eight type groups browse drafts; tag filtering is case-insensitive and suggestions reuse available campaign/draft tags. Find drafts by title alongside the type and tag filters. Review export opens export controls and history on demand. Changing a type never rewrites the body.

**Card preview** shows a portrait card with saved artwork (or the bundled placeholder) and your authored summary. Long summary/tag content scrolls; absent summaries remain explicit. **Open full document** shows safely rendered Markdown with the existing reader tools. Local headings and clicked HTTP(S) links work. Checked source links open the captured source reader; unique draft links open that draft with unsaved-edit protection. Missing, ambiguous, and unsafe targets remain unavailable. The reader identifies the checked capture; replaced captures require rechecking. Raw HTML is escaped and authored images are omitted; placeholder artwork is application-owned.

Edits autosave after a short pause; **Saved** means the backend completed the save. Incomplete metadata can be saved, with separate validation issues. Failed saves retain local edits with Retry save and explicit Reload/discard controls. Stale revisions require explicit reload rather than overwriting another browser. Navigation and campaign switching protect unsaved work, and browser close/reload warns while edits remain; forced termination can still lose unsaved edits. **Prepare** retains the originating session context unless a different campaign was selected.

**Copy source** opens the existing captured library without refreshing campaign files. Select a whole document and choose **Copy document to draft**. A copy gets fresh draft/card identities, draft status, a distinct suggested filename in the same directory, exact body text, and retained original evidence. Legacy material needs an explicit content type. Safe unrelated YAML and unknown Workbench fields survive export; structurally unsafe or unsupported metadata blocks copying while its source stays readable. Expand **Original source and retained metadata** to inspect provenance and original text.

**Inspect export** saves pending edits and checks that exact revision, placement, metadata, and links against the captured library and relevant draft revisions. Review the Markdown, errors, and warnings; acknowledge warnings explicitly before **Download Markdown**. Edits invalidate the report, and the backend rejects changed captures/dependencies. Each export retains immutable bytes, SHA-256, placement, checks, and revision; **Export history → Download again** retrieves those same bytes after later edits or source changes. A failed download can be retried from history. Limits include 1,000 drafts per campaign and 1,000 export artifacts per draft, 64 KiB retained front matter, 2 MiB original source evidence, and 3 MiB encoded Markdown.

Place the downloaded file in your campaign repository manually, then explicitly refresh the library. Relative links are checked against that suggested placement; source/draft collisions and unincorporated draft dependencies are warnings. Downloads never replace campaign files. Metadata status and exporting do not approve session use or canon authority. Writing recovery provides the separate draft/history archive described below. Markdown downloads carry portable content, not full draft/revision backups; session archives do not back up Writing drafts.

To prepare a saved draft directly, open a session, choose **Drafts** beside **Sources**, select All or a type, and review the saved revision/card/full document. **Approve revision … and add** validates that exact revision and appends its frozen copy to the session. Move it among source entries using the existing order controls and add item notes. Approval leaves metadata status unchanged; later draft edits never update the prepared copy. Invalid metadata/path or stale draft/session revisions require explicit correction or reload. **Reload saved drafts** obtains newer revisions.

Selected typed entries offer the same playing card and full reader in Prepare and Read. Authored provenance identifies the draft, revision and approval time, with original source evidence for forks. Links use identities frozen at approval: source targets must come from the recorded capture, and draft targets must match the recorded revision. A newer live capture or edited draft does not satisfy an old link. Missing/ambiguous targets stay unavailable. Session archives include authored copies and evidence for independent reading; they do not restore Writing drafts or their retained revision history.

To remove a working draft, select it in Writing and choose **Delete draft**. Confirmation names the draft and explains that its working copy and unsaved edits will be permanently removed, with no undo. The editor clears only after the backend confirms deletion. Campaign files and frozen session contents/notes remain unchanged; the draft disappears from Writing and from newly loaded planner draft lists. A stale planner selection cannot approve a deleted draft.

Retained exports and approved revisions survive deletion and remain in subsequent Writing recovery archives, including their source evidence. Use the recovery workspace to inspect that history and download old exports. A draft that was never exported or approved has no retained revision history; previously downloaded archives/workspaces remain independent and may still contain its earlier working copy. Deletion does not erase those backups.

Deletion pauses autosave, waits for any save already sent, and uses the last acknowledged revision without forcing unsaved edits to save. A conflicting revision requires explicit reload. Failed or uncertain deletion retains local text and pauses automatic saving; retry **Delete draft** or use **Reload / discard local edits** deliberately. The server rejects later saves to a deleted draft rather than recreating it.

**UW2 backend session Library operations:** `GET /api/campaigns/{campaign}/sessions/{id}/library` adds destination-specific membership/update status to the unified catalogue, with the same query/filter semantics. `POST` to that path accepts `revision` (session), `key`, nullable `capture`, nullable `draft` and nullable `draftRevision` from the selected catalogue. It atomically reuses/creates an associated Draft, approves the saved revision and freezes a whole card. Existing whole-card matches return all item IDs in preparation order without modifying content or checking old session/Draft revisions; stale captures and identity conflicts still reject. Sections and foreign-origin imported copies remain distinct. New additions require exact session and representation expectations. `PUT .../library/{item}` explicitly replaces a whole prepared card with the selected saved Draft version of the same origin identity and type, preserving its ID, order, notes and Play state. Replacement requires current session/capture/Draft expectations. Source files are untouched. These backend contracts do not add frontend controls; unified workspace UX remains later work. Current session archives are v8 after UW3.

## Writing recovery

Choose **Writing recovery** from Writing, or open `/writing/recovery` without a selected campaign. **Download Writing archive** backs up one campaign's saved drafts, retained approved revisions and export artifacts, including their original source evidence. Pending edits in the active Writing context must save first. Other browsers' changes are captured at the backend snapshot transaction. Unsaved edits and intermediate revisions that were never retained are not backed up. Keep a copy of the downloaded archive outside the application database.

**Restore Writing archive** validates the entire file and creates a separate, read-only recovery workspace. It does not require the original campaign or folder and never merges, overwrites, registers a folder or changes session contents. Repeated uploads create separate workspaces. Browse current drafts by type, approved revisions and historical exports, inspect card/full-document previews and original evidence, and use **Download original Markdown** for a retained export's exact bytes. Historical source/draft links stay unavailable; no current source is substituted. Retained approved revisions record Writing's immutable snapshots; session-specific approval identities/times remain in session archives. **Download recovered archive** preserves the workspace's history for another restore.

To resume writing, select a current recovered draft, explicitly choose a destination campaign and **Copy to campaign**, then **Open copied draft**. The new draft has fresh draft/card identities and revision zero; its working fields, source evidence and recovery provenance survive. Historical exports/approvals stay in recovery. Inspect placement/links again before a new export, and explicitly approve a new revision for session use. Repeated copies are independent drafts; after an uncertain request result, reload workspaces or inspect destination drafts before retrying.

Writing recovery downloads a portable ZIP with manifest version 4 and retained artwork; image-less UTF-8 JSON uses version 3. These current formats include Source association evidence; older formats are rejected. Limits: 256 MiB portable file/extracted content, 64 MiB Writing manifest, 1,000 current drafts and 10,000 retained approved/exported records and Source associations combined, plus the existing field/evidence limits. Excessive archives fail explicitly without truncation or partial restore. Large histories may exceed these limits; partitioned backups are not provided. Association evidence stays detached in recovery; copying a recovered Draft does not bind it to live Sources. A recovery archive excludes sessions, campaign folders, full source captures, credentials and AI records. It is not a full database backup, and restore does not establish the authenticity of historical evidence. Recovery workspaces are read-only; editing/deleting their history is outside this increment.

## Session preparation and reading

**Card details → Card artwork** selects or replaces one local JPEG/PNG/WebP file in Write; **Remove artwork** restores the placeholder. The local preview is marked unsaved until the save completes. Failed saves retain the selected file and edits for Retry save; conflicts require explicit reload/discard. Existing navigation and browser-close guards include artwork. Saved artwork appears in Write, Prepare draft/prepared thumbnails and card views, Play active/used cards and detached recovery previews. Images load lazily; unavailable artwork shows a retry action while retaining its saved reference and dimensions. API clients can replace artwork through `POST /api/campaigns/{campaign}/drafts/{id}/artwork` using multipart parts `metadata` (JSON `SaveDraft` with `revision`, `fields`, `imageAction: "replace"`) and `image` (one local JPEG/PNG/static WebP). Ordinary JSON saves preserve artwork by default; `imageAction: "remove"` removes it. Changes share the draft revision and save text/artwork atomically. Limits: 10 MiB per image, 40 megapixels and 16,384 pixels per side. Originals are retained for future resizing; embedded original metadata remains in backups. Prepared copies freeze the approved artwork independently of later Write edits or deletion.

Illustrated portable archives use separate binary operations: `POST /api/campaigns/{campaign}/sessions/portable-export` with the existing session-selection JSON, `POST .../sessions/portable-import` with an octet-stream file, `GET /api/writing-recovery/campaigns/{campaign}/portable-archive`, `GET /api/writing-recovery/{id}/portable-archive`, and `POST /api/writing-recovery/portable-import` with an octet-stream file. ZIPs contain `manifest.json` (session v8 or Writing v4) and deduplicated originals; display variants regenerate on import. Session binary import accepts current-format ZIP only; Writing recovery also accepts its current image-less JSON format. Limits are 256 MiB compressed and extracted, existing manifest text/count limits, and 1 GiB temporary processing storage. Only one portable transfer stages/streams at a time; busy/resource-limit failures are explicit and retryable. An archive may fit its portable limit yet exceed the processing budget. Retained history can make a Writing archive too large; partitioned backups remain unavailable.

UI archive controls use the current portable ZIP coordinator and wait for pending Preparation and workspace saves before export. Current-format JSON API exports/imports remain for image-less sessions and include workspace state; illustrated sessions require ZIP. Writing recovery retains its separate current-format image-less JSON operations. Reviewed Markdown downloads remain text-only. Image reads resolve a draft, retained approval/export, prepared item or detached recovery record before serving display/thumbnail variants; there is no global hash or original-image download route. New scoped image and portable operations are described by the running backend's OpenAPI contract.

Choose a campaign and open **Sessions / New session** in the shared header. Give the new session a title and optional objective, or reopen an existing session there. Prepare shows frozen session cards and notes. **Add material** opens unified Library for complete-card selection without changing the prepared selection or notes scope. **Choose adventure material** in contextual or dedicated Library offers the overview and directly linked Scenes as explicit checkboxes. Heading links select the complete Scene; repeated links yield one choice. Additions save sequentially through the normal whole-card operation; progress and **Retry remaining material** retain successes and reconcile uncertain results before retry. Missing/invalid/conflicting targets are blocked. Existing prepared versions are retained until explicit replacement. Historical section-based items remain readable and portable; new Prepare section capture is discontinued. Full-document readers retain heading navigation.

**Session contents** supports 30–50 prepared entries in a compact numbered list. **Find in session** searches saved titles/source context while retaining the original session numbers and order. Select an entry to inspect its frozen copy and show its up/down/remove controls. Clearing the find brings the selected entry back into view. Hide/show the library, contents, or notes to recover reading space. This local find is independent of full-content source search.

Library and contextual references search saved Drafts and captured Sources inclusively by default, including incomplete, conflicting, guidance/tooling and superseded material. **Type** starts at **All types**; choosing a type deliberately narrows to recognized metadata. Resetting to All types keeps the query; **Clear search** keeps the chosen type. Search covers effective saved full content with Draft precedence, without rescanning campaign files. Result rows show metadata status and preparation readiness; invalid, conflicting and non-session material remains blocked from preparation. Source refresh remains explicit.

Unified catalogue entries show declared title/type and optional authored summaries, with path/issue fallbacks. Search finds effective saved cards, respecting Draft precedence. Inspection never adds material. Adventure selection uses the complete-card journey described above. Guidance/tooling and invalid declarations cannot be prepared; backend validation remains authoritative.

Both source and prepared readers offer **Document outline**, section focus, **Expand all**, and direct access to an authored **Quick reference**. Valid typed cards distinguish exact Read aloud and Mechanics headings visually. Only exact Background and Design notes subtrees start collapsed; names are matched after case/whitespace normalization. **Show Background** / **Show Design notes** and the outline disclose them, while search and source/captured links reveal their exact targets before focusing. Unknown headings and legacy/invalid material remain visible; ambiguous grouping disables automatic disclosure and unsafe section focus. No summary or quick-reference text is invented or imported from outside a selected subtree. Source provenance and frozen classification/relationship availability remain inspectable.

In Prepare, **Focus source** hides session contents and notes, retaining the frozen reader. **Restore panels** restores their prior visibility; individual contents/notes switches remain available. Library selection uses the temporary picker or dedicated Library workspace. These presentation controls do not change session contents or saved Markdown.

Prepare opens selected material as a full document, with **Card** available as an alternative. Saved drafts and approved prepared copies show their own artwork in thumbnails and card views. Source/search entries and cards without artwork use the bundled placeholder. Artwork is centered and cropped within the existing dimensions; full-document readers stay text-only.

Prepared material is a frozen copy of captured Markdown, with source provenance. Changing, removing, excluding, or refreshing the original never rewrites an existing prepared item. Links resolve only to material captured into the session from the same original capture; unavailable targets are identified. Images are omitted, raw HTML remains escaped, and external HTTP(S) links require a click.

In Prepare, the notes page edits session or selected-item Markdown with a rendered preview; **Session details** edits the title and objective. Changing one note requests its preview without re-rendering every item's notes. Text edits autosave after a short pause; **Saved** means the backend completed the save. Failed saves retain local edits and show **Retry save** and **Reload / discard local edits**. Conflicting revisions require an explicit reload rather than overwriting another browser's changes. Leaving a session waits for pending edits or asks whether to discard failed local edits. Browser close/reload warns when edits remain; forced termination can still lose unsaved changes.

**Play** shows a reserved active Scene slot and two runtime piles. Each prepared card is in exactly one location: Session Cards, either pile, Used or the active Scene slot. **Activate Scene / Change Scene** opens explicit related prepared cards and current pile contents. **Keep current piles** changes only the Scene, removing the incoming Scene from its former location if needed; **Customize placements** chooses movements and confirms them atomically. Cancel changes nothing. The outgoing Scene returns to the front of Session Cards. An active Scene cannot be dragged or marked Used; **Deactivate Scene** returns it without clearing piles.

Each pile shows its cover, optional name and count. **Previous / Next** changes only the cover. **Show all** opens a temporary pile dialog for reading, choosing the cover, precise ordering, naming and individual movement. Use a card's drag handle or **⋯** menu; dragging a cover transfers that card, not its pile. Closed-pile drops append. A departing cover advances to the next ordered card, wrapping from the end. **Used cards** holds set-aside cards, with explicit return to Session Cards or either pile. New and returned unassigned cards enter the front; initial Session Cards follow preparation order. Reopening restores placements, names, covers and active Scene independently of preparation order.

The right supporting panel switches **Notes / Document** in the same space. Notes defaults on Play entry and shows Preparation Session/Item notes read-only until P5. Clicking a card or **Open full document** selects its complete frozen Markdown reader; changing a pile cover does not replace that document. Switching back to Notes and Document retains the document selection. **Find cards / Card group** filter Session Cards and Used; covers and open pile contents stay visible. Clear filters before dragging filtered collections. **View** hides/shows Session Cards, while **Notes** toggles the supporting panel. Cards retain 243:420 geometry, 320px default width, frozen artwork, keyboard-scrollable text and full-document access; laptop containers shrink cards and narrow screens stack the slots/panel. Short screens scroll the page.

Play saves explicit movements, ordering and Scene choices with independent revision checks. A failed action retains its intent and offers **Review / retry table action** and **Reload / discard table changes**. Retry checks saved state first; a changed or uncertain arrangement requires explicit review and a new choice rather than replaying against a newer revision. Navigation waits for commands or asks whether to discard retained intent. Campaign/session switches cannot redirect an in-flight command. The shared header retains campaign/session selection, management, session details and export. Prepare resumes editing frozen preparation and notes; actual-play journals and session lifecycle records remain future work.

**Export session** and the session chooser export/import portable ZIP session manifest version 9, including frozen text/artwork/provenance, preparation notes, ordered Session Cards/Used, two runtime pile memberships/names/covers and explicit active Scene. Unopened workspace null is preserved. Imports create new session/item IDs and map placement, pile-cover, Scene and Scene-association references; original resource provenance stays frozen. Old session ZIP/JSON versions 1–8 are rejected; no conversion is provided for disposable historical artifacts. Limits remain 256 MiB per portable file/extracted content, 20 MiB session manifest, 100 sessions, 1,000 prepared items total, 10,000 Scene associations per session and 2 MiB per text/note field. These archives are not full database backups. PlayNotes arrive in a later separately authorized increment, together with their archive support.

Increment 3A adds backend classification of typed Markdown cards, filtered source APIs, and captured link relationships using the [version 1 front-matter convention](../increment-3-typed-markdown-cards.md#accepted-version-1-metadata-contract--2026-10-18). Invalid metadata remains readable with classification issues. Explicit guidance/tooling cannot be added to sessions. Increments 3C.1–3C.2 provide the B workspace, large-session navigation, typed categories/filters and explicit adventure assembly above. Increment 3C.3 provides the production outline/disclosure/focus/search-reveal controls and integrated developer handover above; owner review and formal verification remain separate. Increment 3B freezes classification, authored summary, relationships, and interpretation when adding source material. New captures omit recognized front matter from display while retaining exact raw text/hashes. Existing prepared items and v1 imports keep their legacy text and rendering; current sources never backfill their labels. Source refresh, renames, splits, and deletion do not rewrite prepared metadata or make uncaptured links available.
